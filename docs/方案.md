# dsh-peer-link 完整方案

> 版本：v1.0　编写日期：2026-11-15
> 目标：在本地 DSH 桌面版里直接使用远端设备上的 DSH，形态由 Qoder「设备连接」引发。
> 仓库：`Darren-Guo/dsh-peer-link`（现有原型代码为基础）
> 本文所有技术结论均来自对本机已安装 DSH 的源码/文档查证，未验证项单独标注。

---

## 一、目标与非目标

### 目标

1. 在 A 机器的 DSH 侧栏里出现 `[Mac] default-workspace` 这样的远端工作区
2. 点开后**在本地窗口内**看到远端 DSH 的界面，且是**已登录状态**
3. 任务在远端执行（远端的 agent、远端的文件、远端的模型额度）
4. 不复制、不伪造远端会话日志
5. 传输层只认可达 IP，不绑定任何特定网络（tailnet / 局域网 / VPN 都行）

### 非目标

| 不做 | 原因 |
|---|---|
| 把远端回合写进本地会话日志 | 违反 DSH「会话日志是唯一真相」，且是复制语义，会分叉 |
| 完整文件系统镜像（C 方案） | 已有 SSH workspace 类插件在做，重写不划算 |
| 跨公网中继 | 有 tailnet 就够，不做云中转 |
| 手机客户端 | 不是本项目范围 |

## 二、已查证的事实（方案的依据）

### 2.1 DSH 的客户端/宿主模型

| 事实 | 来源 |
|---|---|
| 一个 Client 只连**一个** Host；`InvokeRemoteRequest.peer` 每次必填，Gateway 从不给默认 Peer | `@deepseek-ai/dsh-api-gateway` README |
| Peer 是**Host 内部的主体**（属主 + 被授权的观看者），不是跨 Host 的连接 | `@deepseek-ai/dsh-api-remote-access` README |
| 非属主 Peer 按「资源 + 角色」受 ACL 约束；属主免检 | 同上 |
| LiveShare 让观众打开的是**被分享方 Host 提供的页面** | `dsh-experimental-liveshare` |

**推论**：本地桌面客户端无法同时挂本地 Host 与远端 Host。所以「本地原生 Chat 显示远端会话」做不到；能做到的是「在本地窗口里呈现远端自己的原生界面」。

### 2.2 工作区注册

| 事实 | 来源 |
|---|---|
| `ctx.workspaceRegistry.create(path, title)` 要求 path **在本地真实存在**；相对路径、盘符相对路径、不存在的路径、文件都会被拒 | `@deepseek-ai/dsh-workspace` README |
| 会话靠 **recorded directory** 归属工作区 | 同上 |
| `project.setTitle()` 可改名 | 同上 |

**推论**：远端工作区必须用**本地影子目录**做锚点。

### 2.3 远端执行能力

| 能力 | 来源 |
|---|---|
| `ctx.agents` 可创建/恢复 agent、`followup()` 投递提示词、`inject()` 注入上下文、`whenIdle()` 等空闲 | `@deepseek-ai/dsh-agent` README |
| `ctx.sessionController` 提供 create / resume / prompt / follow 历史 / 项目化实时状态 | `@deepseek-ai/dsh-api-session-controller` README |
| `session/prompt` 会在 Remote 方法里构造 `user-rpc` 消息来源，是受支持的操作 | 同上 |

**结论**：**本方案不依赖这些 API**（见 2.4），但它们是「若将来要自绘面板」的现成接口。

### 2.4 DSH web 认证机制

| 事实 | 值 |
|---|---|
| 换票入口 | `GET /?token=<launchToken>` → 303 到 `./` |
| cookie 名 | `dsh-auth--<authority 哈希>` |
| cookie 内容 | `{version, authority, issuedAt, expiresAt}`，用**进程内 secret** 签名 |
| cookie 属性 | `HttpOnly; SameSite=Strict; Max-Age=2592000`（30 天） |
| 校验 | `payload.authority === 请求 Host 头里的 authority` |
| launchToken | 进程内存随机值（`randomBytes`），**进程重启即变** |

本地实测补充：

```
8147   127.0.0.1    DeepSeek Harness 进程   ← 桌面版自己的服务
12790  100.64.0.1   DeepSeek Harness 进程   ← 同一套，绑 tailnet 地址
无 token 访问 → 401 "dsh web authentication required"
带 token 访问 → 303 + Set-Cookie
响应头：无 X-Frame-Options、无 Content-Security-Policy
```

### 2.5 业界先例：dsh-Go

`ccch1mneyyy/dsh-Go`（Flutter Android 客户端，23.3k 星，AGPL-3.0）已验证同一条路：

| 事实 | 依据 |
|---|---|
| 连远端两条路：SSH 主机、DSH Remote（自研插件 + 配对 + P2P/Relay 回落） | `docs/guide/zh/03-engine-hosts.md` |
| SSH 主机分「托管启动」（默认跑 `dsh web`）与「只连接」（填端口 + **DSH 登录令牌**） | 同上 |
| 「网页模式」可内嵌 DSH 完整网页界面 | `docs/guide/zh/05-web.md` |
| 网页模式：本机 ✅、SSH 主机 ✅、DSH Remote ❌（中转不放行 HTTP） | 同上 |
| 实现方式是 **TCP 端口转发**，不是 HTTP 反代 | `app/lib/remote/ssh/local_forward.dart` |
| 本地监听 `127.0.0.1:<临时端口>`，每个 socket 管道到远端 `dsh web`；**本地端口在重连之间保持不变** | 同上注释 |
| 被控主机可装桥接插件，对外提供自有端点 `/dsh-go/*` | `docs/plugins/hosts.md` |

> ⚠️ **许可提醒**：dsh-Go 是 AGPL-3.0。本项目 MIT。**只借鉴设计思路与接口语义，不复制它的任何代码**，否则会引入 AGPL 传染风险。

## 三、架构决策

### 3.1 定稿

```
┌──────────────────────── 本地机器（A）────────────────────────┐
│ DSH 桌面版                                                     │
│  ├ 侧栏：本机工作区（原生）                                     │
│  │   个人 / CAD / 彩票 / …                                    │
│  ├ 侧栏：[Mac] default-workspace  ← 影子目录锚定的真实工作区     │
│  │   点开 → 客户端 slot 页面 → iframe                          │
│  │              ↓ http://127.0.0.1:<固定端口>                   │
│  └ 插件 dsh-peer-link（本地半侧）                                │
│       ① TLS 被控端（别人连我）                                  │
│       ② TLS 客户端（我连别人）                                  │
│       ③ TCP 隧道服务器：127.0.0.1:<port> → 远端 127.0.0.1:12790 │
└───────────────────────────┬───────────────────────────────────┘
                            │ 我们的协议（mTLS + 票据）
                            │ 隧道建立后：原始字节双向转发
┌───────────────────────────▼───────────────────────────────────┐
│ 远端机器（Mac）                                                │
│ 插件 dsh-peer-link（远端半侧）                                  │
│   ├ 配对码 / 指纹固定 / 票据校验                                │
│   ├ 工作区与策略服务                                           │
│   └ 隧道出口 → 127.0.0.1:12790（它自己的 DSH web 服务）         │
└───────────────────────────────────────────────────────────────┘
```

### 3.2 为什么是「TCP 隧道 + iframe」而不是别的

| 备选 | 否决理由 |
|---|---|
| HTTP 反代 | 要自己处理 Host、cookie、WebSocket 升级、SSE；而同一件事用 L4 隧道**全都不需要** |
| 自绘面板 | 界面不是原生的，且要自己追 DSH 的 UI 变化 |
| 注入本地会话日志 | 复制语义、违反日志唯一真相、破坏 fork/resume |
| 桌面串流（RustDesk） | 保留为「要真桌面体验」时的备选，但带宽重、不解决工作区集成 |

L4 隧道的决定性优势：DSH 的 cookie 是 `authority 绑定 + SameSite=Strict`，隧道下浏览器看到的地址就是 `127.0.0.1:<port>`，Host 头天然一致，换票和 cookie 全部自然成立，**我们一行 HTTP 逻辑都不用写**。

### 3.3 与远程桌面（RustDesk）的分工

| 需求 | 答案 |
|---|---|
| 想在本地窗口里用远端 DSH 的工作区 | 本方案 |
| 想要远端**完整桌面**（别的软件、系统操作） | RustDesk / Sunshine |
| 两者都要 | 共存，互不冲突 |

## 四、协议

### 4.1 基础（已实现并跨机验证）

TLS（双向 mTLS，配对时固定指纹）之上按行分隔 JSON。

```
配对：8 位码（默认 120 秒，可调，一次性）
认证：deviceId + 证书指纹 + HMAC 票据（24h）
授权：被控端维护 grants；控制端不能改
```

现有方法：`ping`、`workspaces.list`、`workspaces.get`、`session.list`、`session.open`

### 4.2 新增方法（本方案核心）

#### `device.info`

```
→ {"method":"device.info"}
← {"ok":true,
   "device":{"id":"…","name":"mac","fingerprint":"…"},
   "platform":"darwin",
   "dsh":{"port":12790,"tokenAvailable":true,"version":"0.2.1-rc.5"},
   "workspaces":[{"id":"…","name":"default-workspace","path":"/Users/…"}]}
```

#### `tunnel.open`

```
→ {"type":"tunnel","deviceId":"…","ticket":"…","port":12790,"connId":"…"}
← {"type":"tunnel-ready","connId":"…"}      // 之后该连接退化为原始字节管道
← {"type":"rejected","reason":"…"}          // 未授权 / 端口未在白名单
```

规则：

- `port` 必须在该 grant 的**端口白名单**内（默认只允许 DSH 自身端口 + 显式放行的端口）
- 隧道建立后，服务端把该 socket 的后续字节双向拷到 `127.0.0.1:<port>`，**不再解析任何协议**
- 单个隧道连接最大生命周期由票据有效期约束

#### `dsh.token`

```
→ {"method":"dsh.token"}
← {"ok":true,"token":"<launchToken>","authority":"100.64.0.4:12790"}
```

用途：控制端拿它拼出 `http://127.0.0.1:<本地端口>/?token=…` 一次性换票。
取不到时返回 `{"ok":false,"reason":"token-unavailable"}`，控制端退化为**让用户手工粘贴令牌**（与 dsh-Go「只连接」模式一致）。

### 4.3 与现有原型的差异

| 现有实现 | 最终实现 |
|---|---|
| `session.list` 扫 session 文件目录 | 保留（用于侧栏展示/搜索），但**不作为打开远端的依赖** |
| 读投影缓存判断会话 | 保留，仅用于列表 |
| 无隧道 | 新增 `tunnel.open` |
| 无 token 获取 | 新增 `dsh.token` |

## 七、安全模型

| 层 | 机制 |
|---|---|
| 配对 | 8 位码，默认 120 秒，一次性消费，交换后立即作废 |
| 传输 | 双向 mTLS，双方固定对方证书指纹；客户端也校验服务端指纹（防中间人） |
| 授权 | HMAC-SHA256 票据，绑定 `deviceId + 指纹`，`timingSafeEqual` 比对，24h 过期 |
| 粒度 | 工作区白名单 + **端口白名单**（隧道只能连白名单端口） |
| 撤销 | 被控端本地操作，立即生效；隧道在建连接随下一次校验失效 |
| 权限方向 | **控制端不能改策略**；改策略/撤销只能被控端本地做 |
| 影子目录 | 空目录，不含任何远端数据，agent 不应在其中工作 |

### 默认端口白名单

```json
[12790]
```

即：默认只能隧道到 DSH 自身的 web 端口。要转发别的端口必须在被控端显式加。

### 明文存储

当前原型把私钥明文放在 `data/<name>.json`。**最终版必须改**：

- Windows：DPAPI（`CryptProtectData`）
- macOS：Keychain
- Linux：Secret Service / 600 权限 + 明确告知

## 八、实施计划

### P0　隧道 SPIKE（半天）— ✅ 已完成

目的：用最小代码回答唯一剩下的技术问题。

**实测结果（2026-11-15）**

| 验证项 | 结果 | 证据 |
|---|---|---|
| L4 隧道转发 `127.0.0.1:54321 → 100.64.0.1:12790` | ✅ | 无 token 401、带 token 303、带 cookie 200 |
| 换票 cookie 的 authority | ✅ | 解码为 `127.0.0.1:54321`（隧道地址，非远端地址） |
| 页面完整性 | ✅ | 200，47,354 字节 |
| 无 CSP / X-Frame-Options | ✅ | 响应头与页面内均无 |
| **iframe 嵌入（同站父页面）** | ✅ | 在 `http://127.0.0.1:54322/` 中的 iframe 里渲染出完整 DSH 界面 |
| **客户端数据层** | ✅ | 会话列表、工作区列表正常加载 = RPC 通道过隧道正常 |
| iframe 嵌入（`file://` 父页面） | ❌ 预期失败 | `SameSite=Strict` cookie 跨站不发送 → 401 |

**结论：方案 A 技术成立。**

**新增约束（必须写进实现）**

> iframe 的父页面必须与隧道地址**同站**。

DSH 的认证 cookie 硬编码 `SameSite=Strict`，父页面若是 `file://`（opaque origin）或不同站点，cookie 不会发送，iframe 内必然 401。
DSH 桌面窗口运行在 `http://127.0.0.1:8147`，与隧道 `127.0.0.1:<port>` 同为 `127.0.0.1` 站点（端口不参与站点判定），**天然满足**。但如果将来改为 `file://` 加载或改用 hostname，嵌入会失效。

**副产品：不需要任何 HTTP 层处理**

原方案设想的「保留 Host 头」「注入 cookie」全部作废。L4 原样转发下，浏览器自己填的 Host 就是隧道地址，远端据其计算 authority 并签发 cookie，整条链路自然一致。

| 6 | DSH 升级后 web 认证机制变化 | 断链 | token 获取与换票集中在一处，便于适配 |
| 7 | 影子目录被 agent 误用 | 数据错觉 | 目录名带 `[远端]` 语义、README 写明、必要时加 `.keep` 说明文件 |
| 8 | **AGPL 传染** | 法律 | 不复制 dsh-Go 代码，只参考设计 |
| 9 | **父页面与隧道地址不同站** | iframe 内 401 | P0 已实测；实现时固定用 `127.0.0.1`，禁止 `file://` 或换 hostname |
